# Languages

The editor, the panel page and the dashboard page speak English, Spanish, French,
Italian, German, Norwegian (Bokmal), Bulgarian, Greek, Korean, Japanese,
Vietnamese, Hindi, Simplified Chinese and Arabic. Arabic is laid out right to left.

A person picks a language from the picker in the top bar, on the sign-in page and
on the panel page. The choice is remembered in the browser. Until they pick one,
the browser's first language that we speak is used, and English when there is none.

## What changes and what does not

Only the words a person reads change. A flow file, a node type name, a property
name, a port name and a saved flow are never touched. Node type names (`inject`,
`mqtt in`, `modbus read`), protocol and product names (Modbus, OPC UA, HotLoop,
FlowLab) and units stay in English in every language.

Numbers and dates are written the way the language writes them, through `Intl`.
Digits stay 0 to 9 in Arabic and Hindi, because a plant reads a setpoint as 1450.
The node canvas keeps its own left to right coordinates in Arabic; everything
around it is mirrored.

## Where the words live

| What | Where |
|---|---|
| The editor and the panel page | `web/src/i18n/ui.<code>.json`, one flat key to text file per language |
| What each node type says (help, field labels, placeholders, choices, port labels) | `internal/i18n/catalog/nodes.<code>.json`, keyed from the descriptors in Go |
| The dashboard page's own few words | `internal/dashboard/web/i18n/<code>.json` |

English is the source. The node descriptors in Go stay in English, and
`go test ./internal/i18n -run English -update` writes `nodes.en.json` from them.
`GET /nodes?lang=de` answers with the same node types and the German text. Without
`lang` the answer is English, as it always was.

A count that changes the wording is a family of keys, `key_one` and `key_other`, and
`key_zero`, `key_two`, `key_few`, `key_many` where the language has them (Arabic
does). The editor picks the form from the language's own plural rules.

## Adding or changing a string

1. In a component, write `tr('area.name')`, never the text. In a library file
   import `tr` from `lib/i18n.svelte`. A value goes in as `{name}`; never join
   translated pieces in code.
2. Add the English to `web/src/i18n/ui.en.json`, and the same key to every other
   `ui.<code>.json`, using the term base in the codex (`work/notes/i18n/glossary`).
3. For a node type, change the descriptor, run the `-update` command above, and add
   the new keys to every `nodes.<code>.json`.

`go test ./internal/i18n` fails when a language is missing a key, when a `{name}`
or a code span changed, when a plural form is missing, when a component carries a
word that is not behind `tr()`, and when a key a component asks for has no English.
A node string still in English is listed in `catalog/untranslated.nodes.<code>.json`;
a new string cannot join that list by accident.

Strings that a person is unsure of are listed in `lowconfidence.ui.<code>.json` and
`lowconfidence.nodes.<code>.json`. A native reader should look at those first.

## What the runtime says

Errors from the admin API arrive in English. The editor shows the ones it knows
(`server.*` keys) in the person's language and the rest as the runtime wrote them.
