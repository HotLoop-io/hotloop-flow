HotLoop Flow 2.12.1 is 2.12.0 with the arm64 image added, and nothing else. 2.12.0 shipped amd64 only so it could get to production and read stable first, and it did: a plant has run it clean. This is the one small bump that builds both. There is no change to the code, the chart, the settings or your flows.

## What changed

- The image is built for linux/amd64 and linux/arm64. The `2.12.1`, `2.12` and `2` tags hold both. The `2` tag was still on 2.11.1 until this release.
- The README and the install pages name 2.12.1 and say amd64 and arm64.

## New settings

None.

## Upgrade

A plain `helm upgrade` to the 2.12.1 image and chart, or the new tag in your Quadlet unit. If you are on arm64 and stayed on 2.11.1 while 2.12.0 was amd64 only, this is your move to the finished panel controls, sub-diagrams that open in place and the instrument write switch: read the 2.12.0 notes for what they are, what isn't proven, and the one change that can stop a running diagram (a diagram that drives an instrument is refused with code 5007 until that instrument's writes are switched on). Nothing happens on first start and nothing needs migrating.

## What isn't proven

The arm64 image is built under emulation on the runner, and it starts and reports its version in the release run. It has not been run on an arm64 box for this release.

Image: `ghcr.io/hotloop-io/hotloop-flow:2.12.1`, linux/amd64 and linux/arm64. Chart: `https://hotloop.io/hotloop-flow/`. The README at this tag has the rest, with pictures: https://github.com/HotLoop-io/hotloop-flow/blob/v2.12.1/README.md
