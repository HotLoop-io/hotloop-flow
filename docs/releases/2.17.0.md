HotLoop Flow 2.17.0 makes the flows you bring over from Node-RED and the VIs you bring over from LabVIEW behave the way they did where they came from, and it lets you ask a running Flow exactly which build it is. Nothing in your flows, settings or chart changes.

## What changed

- **A Function node can use the names Node-RED lets it use.** A function body that declares its own `const context`, `flow`, `global`, `env` or `util` used to fail to compile here, and the node did not start. In Node-RED those names are not locked, so a flow that does this came across silent. It now starts and runs as it did there. `msg` and `node` are still taken by Flow, as they are in Node-RED.
- **The CSV node says which columns it used.** After it turns text into rows, or rows into text, `msg.columns` holds the column names, the way Node-RED's node leaves them. A flow that reads a table, adds a column in a change node and writes the table back out now keeps every column. Before this, the header and the data lost them.
- **A CSV node's own column list comes first.** If you typed the columns into the node, those are the ones it uses. `msg.columns` only names the columns for a node that has none typed in. This is how Node-RED decides, and a flow that depends on it now gives the same file.
- **`hotloop-flow version` names the commit.** The version command prints the commit the image was built from after the version number, so when a plant reports a problem you can tell which build it is, even for an image that was built from a branch.
- **Proved on more than the examples.** FlowLab's LabVIEW reader was run on all 425 VIs in NI's published icon editor project, and for every one of them the number of wires it reads equals the number an independent reader finds in the same file. Not one file was refused, and every wire starts at a node and ends at a node. We also ran 35 flows from the public Node-RED library on real Node-RED 5.0.10 and on Flow: 22 of the 24 whose output does not depend on a clock give the same output, and the two that differ are written in `docs/node-red-types.md`.

## New settings

None.

## Upgrade

A plain `helm upgrade` to the 2.17.0 image and chart, or the new tag in your Quadlet unit. Nothing happens on first start and nothing needs migrating. A flow file loads and saves byte for byte as before. This release builds the amd64 image. The `2` tag keeps the arm64 image it already holds from 2.16.1, and a small follow-up release with nothing else in it, 2.17.1, brings arm64 back. If you are on arm64, stay on 2.16.1 until then.

One behavior to know about: a CSV node that has its own columns typed in and also receives `msg.columns` now uses the ones typed in. If a flow relied on `msg.columns` winning, clear the node's column list.

## What isn't proven

The Node-RED library run covers flows that use only Node-RED's own nodes. A Function node that loads a module from npm still cannot run in Flow, and one such flow is among the two that differ. A Debug node shows a message longer than its Length setting cut in a different place than Node-RED does, which changes what the sidebar shows and not what the flow does. The LabVIEW reader still does not know what each LabVIEW primitive does, because that table is NI's and is not in the file, so a primitive arrives as a named node that stops the diagram. The check on the 425 VIs ran in the lab.
