HotLoop Flow 2.9.1 lets the `modbus-server` node listen on one VLAN's interface, so one Flow can run a server on each VLAN of a port at the same address and port.

## What's new

- **`modbus-server` takes a network interface.** The listening socket is bound to the interface (`SO_BINDTODEVICE`) before it listens, so two servers on `192.168.1.9:10502` on two VLANs no longer collide. The setting is the same as on every client: the node's own **Network interface**, else `FLOW_NETWORK_INTERFACE` in its tab's environment variables. With neither, it listens as it always did, and two servers on one address and port still collide, now with an error that says each needs an interface.

## What changed

- The patched Modbus library copy in `third_party/modbus` has one more hook, a listener, next to the dialer from 2.9.0. Unset, it behaves as the upstream does. NOTICE and `HOTLOOP_PATCH.txt` say what changed.

## New settings

None beyond the **Network interface** field on `modbus-server`. The chart value `bindToInterface.netRaw` and the host-network requirement from 2.9.0 apply to it as they do to the clients.

## Upgrade

A plain `helm upgrade` to the 2.9.1 image and chart, or the new tag in your Quadlet unit. Nothing happens on first start and nothing needs migrating. A flow that sets no interface behaves exactly as it did on 2.9.0.

## What isn't proven

It was proven on The Beast in a lab of two network namespaces that share `192.168.1.0/24`, with a Modbus client in each reading its own server for 20 rounds with no crosstalk, and the same two servers unbound colliding. A kernel before 5.7, where binding needs `CAP_NET_RAW`, was not run, and nothing ran on a plant's own network.
