HotLoop Flow 2.16.3 is 2.16.2 with the arm64 image added, and nothing else. 2.16.2 shipped amd64 only so it could get to production and read stable first, and this is the one small bump that builds both. There is no change to the code, the chart, the settings or your flows.

## What changed

- The image is built for linux/amd64 and linux/arm64. The `2.16.3`, `2.16` and `2` tags hold both.
- The README and the install pages name 2.16.3 and say amd64 and arm64.

## New settings

None.

## Upgrade

A plain `helm upgrade` to the 2.16.3 image and chart, or the new tag in your Quadlet unit. The chart takes its image tag from its own version, so a chart install of 2.16.2 pulled an amd64 image: on an arm64 box, move to 2.16.3. If you are on arm64 and stayed on 2.16.1 while 2.16.2 was amd64 only, this is your move to the CPU and memory fixes in the 2.16.2 notes. Nothing happens on first start and nothing needs migrating.

## What isn't proven

The arm64 image is built under emulation on the runner, and it starts and reports its version in the release run. It has not been run on an arm64 box for this release.

Image: `ghcr.io/hotloop-io/hotloop-flow:2.16.3`, linux/amd64 and linux/arm64. Chart: `https://hotloop.io/hotloop-flow/`. The README at this tag has the rest, with pictures: https://github.com/HotLoop-io/hotloop-flow/blob/v2.16.3/README.md
