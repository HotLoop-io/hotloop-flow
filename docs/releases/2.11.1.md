HotLoop Flow 2.11.1 is 2.11.0 with the arm64 image added, and nothing else. 2.11.0 shipped amd64 only so it could get to production and read stable first, and it did: a plant ran it with 13,727 nodes and no restarts. This is the one small bump that builds both. There is no change to the code, the chart, the settings or your flows.

## What changed

- The image is built for linux/amd64 and linux/arm64. The `2.11.1`, `2.11` and `2` tags hold both.
- The README and the install pages name 2.11.1 and say amd64 and arm64. The README's install line in 2.11.0 still pointed at the 2.10.2 image; it names 2.11.1 now.

## New settings

None.

## Upgrade

A plain `helm upgrade` to the 2.11.1 image and chart, or the new tag in your Quadlet unit. If you are on arm64 and stayed on 2.10.2 while 2.11.0 was amd64 only, this is your move to the case structure editor, selection to sub-diagram, tidy layout, named wires, zoom to 400 percent, node symbols, the panel object setter and the diagram write gate: read the 2.11.0 notes for what they are and what isn't proven. Nothing happens on first start and nothing needs migrating.

## What isn't proven

The arm64 image is built under emulation on the runner, and it starts and reports its version in the release run. It has not been run on an arm64 box for this release.

Image: `ghcr.io/hotloop-io/hotloop-flow:2.11.1`, linux/amd64 and linux/arm64. Chart: `https://hotloop.io/hotloop-flow/`. The README at this tag has the rest, with pictures: https://github.com/HotLoop-io/hotloop-flow/blob/v2.11.1/README.md
