HotLoop Flow 2.5.0 is a new editor. Same flows, same engine, same shortcuts, and it finally looks like it belongs next to the rest of HotLoop instead of like it came from a different company. If you wire plants for a living, what you get is a screen that fits what you actually do all day: put the thing on the canvas, deploy it, and watch it run.

## What's new

**The editor looks like HotLoop.** Same colors, same type, light and dark following your system, with a button in the top bar when you want the other one. Orange means "you can click this" and nothing else. It does not mean a warning, a selection, or a path a message took.

**Debug and runtime moved under the canvas.** The debug log and the Runtime table sit in a dock along the bottom now, side by side, so a debug line gets the whole width of the canvas instead of a skinny column where every payload wrapped four times. The Runtime table next to it still counts what went into and out of every node, with a bar for how full each queue is. What that means for you: you watch a reading arrive and see the node it came from without scrolling or squinting.

**History, Tests and Trace stay on the right.** The one you're working in comes to the top. Press Deploy and the review is the first thing in that column, with the note box under it. Click Trace on a debug line and the trace takes the top spot.

**A trace is blue now.** The path a message took is drawn in blue across the canvas, with the time each node spent on it. The review before a deploy marks added, changed, moved and removed nodes in green, amber, blue and red. What that means for you: you can tell a trace from a selection at a glance now, because they stopped sharing a color.

**A sign-in that looks like it's from the same company.** A card, the real logo, and the same fields. Behind the EmberCORE dashboard it still tells you to come in through the dashboard.

**Search shows its shortcut.** The button says Ctrl F, so you don't have to guess.

**A double-click right after an edit lands.** The editor checks your wire types a moment after every edit, and it used to redraw every wire even when the answer hadn't changed, so a double-click on a node could hit a wire that was being swapped out mid-click and do nothing. It only redraws when something actually changed now.

## What changed

Nothing about your flows. A flow file loads and saves byte for byte, exactly as before. Wiring, dragging, undo, copy and paste, Ctrl+Enter, Escape, nudging with the arrow keys, zoom, marquee select and dragging from the palette all work the way they did, and every one of the 60 browser tests passes without a line of them touched. I also walked every screen and dialog on 2.4.0 and on this build against the same plant flow, 48 states, and nothing went missing.

Things that look different on purpose: the debug and runtime panels moved to the dock, the Tests panel's empty message now says "debug dock" because that's where the log is, a trace and a review are drawn in blue and the status colors, the theme button says Dark or Light, and Search shows its shortcut.

**One thing is slower, and I'd rather say so than have you find it.** The page is blank for a moment until the editor has loaded, where the old one painted its frame first. I measured it with the browser cache off, from sign-in page request to the form on screen. On this machine it's about 12 ms more. Over a 20 Mbps link it's about 100 ms more (230 ms became 335 ms), and over a 1.6 Mbps link with 150 ms of latency it's about half a second more (1.46 s became 1.96 s). On a plant LAN it's a few milliseconds. On a bad link you'll see a white page for a beat, and then the editor. It's a one time cost per page load, not per click.

## New settings

None. There is nothing to turn on, and nothing here has a switch to turn it off.

## Upgrade

A plain `helm upgrade` to the 2.5.0 image and chart, or the new tag in your Quadlet unit. Nothing happens on first start, there is nothing to migrate, and the flows, the deployment records and the credentials are not touched. Reload the editor tab once after the pod restarts so your browser stops showing the old one.

## Licenses

The editor ships two typefaces now, Inter and JetBrains Mono, under the SIL Open Font License 1.1. Their licenses are in `/usr/share/doc/hotloop-flow/THIRD_PARTY_LICENSES` with the rest, and `NOTICE` says how that file is made.

## What isn't proven

The browser tests and the screenshots run in Chrome. I haven't opened this editor in Firefox or Safari, on a tablet, on a plant HMI screen, or inside the live EmberCORE dashboard frame (I walked the dashboard's theme message by hand and it matched 2.4.0, but I haven't seen the live frame). If you use Flow from one of those, the first time you open it is the first time anyone did.
