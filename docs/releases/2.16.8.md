HotLoop Flow 2.16.8 makes a flow you bring over from Node-RED behave the way it did there, and it makes sure one odd value can never take your plant's Flow down. Nothing in your flows, settings or chart changes.

## What changed

- **A value that holds itself no longer stops Flow.** Node-RED lets a change node write a list into itself, for example set `msg.payload[0]` to `msg.payload`, and carries on. Flow used to follow that loop until it ran out of stack and the whole process exited. Now the loop is cut where it turns back on itself, that one node reports "the value refers to itself" like any other node error, and every other flow keeps running. The same protection covers a function node that returns, sends or sets such a value. We reproduced it with a real plant's flows, 13,737 nodes answering a Modbus simulator: the old build died inside a minute, this one ran on.
- **Function nodes speak modern JavaScript.** `await`, a promise the body returns, a Setup promise that holds the first message until it settles, and `node.linkcall` all work, so a function written for Node-RED 4 runs as written. An error no Catch node takes is marked unhandled, as Node-RED marks it.
- **Node-RED's own example flows give Node-RED's output.** All 62 recorded examples now match what real Node-RED produced. This release fixes the part counts a switch writes, the type a csv node stamps on its rows, `msg.columns` and `msg.reset` on csv, and reset and flush for messages a delay is holding.
- **FlowLab reads a LabVIEW VI's block diagram.** Nodes, wires, constants, controls, indicators and structure bodies come across, and anything FlowLab has no equivalent for stays visible as a named node so you can see where the diagram stops.
- **A larger, still self-contained binary.** Flow stays one static binary with the editor inside. It is now allowed to grow to 58 MiB to hold all of the above.

## New settings

None.

## Upgrade

A plain `helm upgrade` to the 2.16.8 image and chart, or the new tag in your Quadlet unit. Nothing happens on first start and nothing needs migrating. A flow file loads and saves byte for byte as before. This release builds the amd64 image. The `2.16` and `2` tags keep the arm64 image they already hold from 2.16.1, and a small follow-up release with nothing else in it brings arm64 back. If you are on arm64, stay on 2.16.1 until then.

## What isn't proven

The self-reference fix ran against a Modbus simulator in a lab, not against live PLCs. The LabVIEW reader covers the block diagram as far as the VI file lets it, and primitives it does not know stop the diagram at a named node. FlowLab's LabVIEW support adds a notice to `NOTICE` for the MIT-licensed file-format reference it relies on, and the image carries it.
